## 人の違いを、制作のはじめから考える

アクセシビリティは、完成したデザインの問題点を最後に見つけるためだけのものではありません。誰に、どのように情報や機能を届けるかを考え、要件や情報構造、UI、コンテンツへ反映することから始まります。

このガイドは、達成基準の番号からではなく、人がどのように情報を知覚し、構造を理解し、移動し、操作し、入力するかという視点から、アクセシブルなデザインを考えるためのものです。

## 対象とする人

Web制作で、次のような判断に関わる人を対象としています。

- 要件や品質目標を決める
- 情報構造、ユーザーフロー、ワイヤーフレームを設計する
- ビジュアル、UI、インタラクション、コンテンツを具体化する
- デザインをレビューする
- デザイン上の意図を実装へ引き継ぎ、維持する

職種を一つに限定するものではありません。プロジェクトマネージャー、ディレクター、デザイナー、コンテンツ制作者、エンジニアが、同じPracticeをそれぞれの制作フェーズから参照できます。

## ガイドの構成

### Human Lens

人がWebを利用するときの体験を、7つの問いから捉えます。特定の障害名だけで利用者を分けず、恒久的な違いに加えて、一時的な状態、利用状況、環境によって起こる困難も考えます。

### Practice

要件、情報設計、デザイン、コンテンツ、レビューで行う判断の単位です。51件のPracticeには、考える理由、検討の手がかり、さらに問いを広げるための視点があります。

### By Phase

Practiceを`Decide`、`Design`、`Review`の三つの制作フェーズから探せます。職種ごとに別のルールを持つのではなく、同じPracticeを、いつ決め、具体化し、確認するかで整理しています。

### Standards

WCAG 2.2 Level A・AAの達成基準から、対応するPracticeを逆引きできます。規格上の要求を確認したいときや、Practiceの背景をたどりたいときに使います。

## 使い方

最初にすべてを順番に読む必要はありません。

1. 初めてアクセシビリティを考えるときは、関心のあるHuman Lensから、人の体験と問いを読む
2. 制作中は、現在のフェーズに対応する一覧からPracticeを選ぶ
3. 個別のデザイン判断やレビューでは、関連するPracticeの本文と適用条件を確認する
4. 規格との関係を確認するときは、Practiceに紐づくWCAGまたはStandardsの逆引きを使う

Practiceは、機械的に消化するチェックリストではありません。案件にいる人、提供する情報や機能、利用される状況を想像し、より多くの人が目的を達成できる方法を対話するために使います。

## Practiceの表示について

### 標準品質 / 案件に応じて判断

このガイドでは、WCAG 2.2 Level Aを基礎に、Web制作の基本品質として重要だと考える一部のLevel AAを「標準品質」として位置づけています。私たちは、これらをロフトワークのWeb制作における最低限の品質として扱える状態を目指します。

「案件に応じて判断」は、やらなくてよいという意味ではありません。対象ユーザー、機能、品質目標、スコープなどを踏まえて適用を判断します。

### 常に確認 / 該当する場合に確認

一般的なWeb制作で確認するPracticeと、動画、フォーム、認証、時間制限など、対象のコンテンツや機能がある場合に確認するPracticeを区別しています。

### Decide / Design / Review

- `Decide` — 要件、情報構造、ユーザーフロー、ワイヤーフレームを決める
- `Design` — 視覚表現、UI、インタラクション、コンテンツを具体化する
- `Review` — 人の違いによる利用しにくさが生まれていないか確認する

### 開発へ引き継ぐ

「開発へ引き継ぐ」は、そのPracticeの責任をエンジニアへ移すことを意味しません。要件、情報設計、デザイン、コンテンツで決めたアクセシビリティ上の意図を、実装でも維持する必要があることを示します。

## WCAG 2.2との関係

WCAG 2.2は、Human LensとPracticeの背景にあるトレーサビリティとして参照します。Level A・AAの55基準をPracticeからたどれますが、これは個別のサイトや成果物がWCAGへ適合していることを保証するものではありません。

また、WCAGのLevelと、このガイドの「標準品質」「案件に応じて判断」は別の分類です。WCAGの正式な要件や適合判断には、W3Cの原文とWAICによる日本語訳を参照してください。

## 対象範囲

このガイドが主に扱うのは、Web制作における要件、情報設計、デザイン、コンテンツ、レビューと、開発への引き継ぎです。HTML、CSS、JavaScript、ARIAなどの具体的な実装方法や、完成後のアクセシビリティ試験を網羅するCoding Guidelineではありません。

アクセシビリティは一度の確認で完了するものではありません。制作の各段階で判断を共有し、実装や運用を通して意図が維持されているかを確かめ続ける必要があります。
